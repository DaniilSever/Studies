# Суперапп — перенос Python/PyQt5 → C++/Qt Widgets

Исходная основа: `System(2).zip`. Вся реализация на C++17 + Qt Widgets/Network, Python не нужен для запуска. Linux-only: чтение `/proc`, `/dev`, запуск `bash` и `xdg-open`.

## Структура

- `src/app.cpp` — точка входа и создание стандартных каталогов.
- `src/settings.h`, `src/settings.cpp` — тексты, параметры, пути и размеры; сообщения скопированы из Python `settings.py`.
- `src/modules/filemanager.{h,cpp}` — `filemanager_ui` / `filemanager_func`, плитки и операции над файлами.
- `src/modules/terminal.{h,cpp}` — `terminal_ui` / `terminal_func` и собственная консоль.
- `src/modules/monitoring.{h,cpp}` — `monitoring_ui` / `monitoring_func`, чтение `/proc` и TCP-сервер.
- `src/popup.{h,cpp}` — просмотр каталога и TCP-клиент с JSON-строками.
- `src/modules/assets/*.png` — **оригинальные** PNG без изменений, 64×64.
- `src/*_main.cpp` — точки входа дополнительных процессов.

## Сборка на NixOS

```bash
cd System_Qt
nix-shell
cmake -S . -B build -G Ninja
cmake --build build -j 4
./build/superapp
```

Для других Linux: нужны C++17, CMake, Qt 6 Widgets и Network (или Qt5 5.15), компилятор C++. Пример:

```bash
cmake -S . -B build
cmake --build build -j 4
./build/superapp
```

Дополнительно доступны `./build/superapp_terminal`, `./build/superapp_monitoring` и `./build/superapp_popup --folder /путь`.

Запускайте приложение из каталога `System_Qt`, находящегося **внутри общего каталога среды**; как у оригинала, его родительский каталог является корнем файлового менеджера. Файлы журналов записываются рядом с исходниками C++.

## Возможности и известные различия

Сохранены: файловые операции, история навигации, скрытые файлы, просмотр свойств, поиск, drag-and-drop (внешний — копирование, внутренний — перенос), стартовые папки и корзина; терминальные команды, чтение `/proc`, таблица мониторинга и отчёты, отдельные окна и TCP/JSON.

Этот перенос **не прошёл компиляцию и GUI/e2e-проверку** в среде подготовки: там отсутствуют Qt development packages. Поэтому поведение не подтверждено как полностью эквивалентное. Отличия на данный момент: упрощённая справка горячих клавиш, сокращённые тексты некоторых ошибок в терминале, `ls` показывает краткий список вместо подробного, `cp` поддерживает один источник, не реализовано автодополнение, popup просмотра папки остаётся текстовым как в оригинале. Обязательно проверьте запуск и функциональные сценарии на NixOS перед использованием реальных данных.

**Осторожно:** операции `rm`, `Shift+Delete` и перемещение файлов затрагивают реальные каталоги. Тестируйте на временной папке.

## Исправления: Drag and Drop и виртуальный корень

- После `setMovement(Static)` повторно настраивается Drag and Drop для списка плиток (перенос внутри окна и копирование файлов из файлового менеджера ОС).
- `SUPERAPP_ROOT` — верхний уровень видимого пространства. Кнопка «Вверх» в этом каталоге выключена; также за него нельзя перейти через поле адреса, историю навигации или символические ссылки, ведущие наружу.
- Съёмные носители из меню «Переход → Съёмные носители...» остаются отдельными корнями. Выше точки подключения кнопка «Вверх» не ведёт.
- Пути каталога и оригинальные PNG не менялись. Терминал, мониторинг, popup и сокетный протокол не изменялись.

Проверка после пересборки: попробуйте перенести файл на значок папки и на пустую область; перетащите внешний файл из системного менеджера; проверьте неактивную кнопку «Вверх» на корне, ручной ввод родительского каталога и переход на USB-носитель.

## Переносимость путей (РЕД ОС / другие Linux)

Никаких абсолютных путей к машине сборки больше не записывается в C++-бинарники через `SUPERAPP_SOURCE_ROOT`. Пути находятся в `src/settings.cpp` и вычисляются при запуске:

- При запуске из `build/` или `build-*` **внутри дерева исходников** (`CMakeLists.txt` и `src/settings.h` находятся на уровень выше), `appRoot` — корень проекта, `SUPERAPP_ROOT` — его родитель, как в старой версии.
- При запуске отдельно перенесённых бинарников `appRoot` — каталог исполняемых файлов, `SUPERAPP_ROOT` — его родитель.
- Ассеты берутся прежде всего из `assets/` **рядом с бинарниками**. При разработке есть резервный путь `src/modules/assets` от корня проекта.
- Журнал записывается в `appRoot/fm_journal.log`, папка `Корзина` и стандартные каталоги — в `SUPERAPP_ROOT`. Остальная логика не менялась.

Чтобы не нарушить защиту системной папки `System` и не перепутать относительные пути, для переноса собирайте готовую структуру:

```bash
cmake -S . -B build-redos -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build-redos -j$(nproc)
bash scripts/package-portable.sh build-redos
```

Получится:

```text
release/SuperApp/
├── System/
│   ├── superapp
│   ├── superapp_terminal
│   ├── superapp_monitoring
│   ├── superapp_popup
│   └── assets/
│       ├── folder-icon.png
│       └── file-icon.png
└── (создаваемые при запуске папки пользователя и Корзина)
```

Перенесите **всю** папку `release/SuperApp` на РЕД ОС; запустите `./SuperApp/System/superapp` из каталога, где находится папка `SuperApp`. Копирование в другое место не изменяет корень. Для работы нужны установленные в РЕД ОС совместимые динамические библиотеки Qt6 и glibc; скрипт их не упаковывает. На компьютере без Qt6 и других зависимостей потребуется отдельная упаковка библиотек.

Также исправлен фильтр `QDir::NoFilter` в режиме скрытых файлов: `.` и `..` не показываются в обоих режимах.
