# Курсовой проект по дисциплине «Операционные системы и оболочки»

## 1. Цель проекта

Разработать под Linux графическое приложение «Суперапп» — файловый менеджер с дополнительными функциями мониторинга ОС, запуска системных утилит, терминала и межпроцессного взаимодействия.

**Предполагаемый стек:** Python + PyQt (предпочтительно PyQt6) для GUI.  
**Платформа:** Linux.  
**Мой вариант:** 5 — трактуется как последняя цифра номера зачётной книжки для пунктов 1–3 задания.

> В методичке отдельный «вариант 5» для дополнительной функции не указан: дополнительную функцию из списка 1–50 назначает преподаватель индивидуально. Если под вариантом 5 подразумевается именно пункт №5 списка, это «информация о звуковой карте» — ниже отмечено как предположение, которое нужно подтвердить.

---

## 2. Что должно получиться

Приложение с главным окном, в котором можно:
- просматривать файлы и папки внутри собственной рабочей корневой директории;
- создавать папки, открывать файлы, копировать, перемещать, удалять и переименовывать элементы;
- удалять элементы в Корзину или безвозвратно;
- работать со съёмными носителями;
- искать файлы и папки во вложенных директориях;
- запускать системные утилиты Linux;
- использовать встроенный терминал;
- видеть список и сведения о процессах;
- открывать дополнительные окна-процессы, получающие данные от главного окна через IPC;
- получать назначенную дополнительную информацию о системе и сохранять её в лог.

## 3. Требования задания и мой вариант

### 3.1. Межпроцессное взаимодействие (IPC)

Для последней цифры зачётной книжки **5** методичка предусматривает **каналы (pipes)**.

Нужно:
- запускать дополнительное окно как отдельный процесс;
- передавать данные из главного процесса в дополнительный через pipe/каналы;
- обеспечить зависимость дочернего окна от главного приложения (при закрытии главного — корректно завершать дочерний процесс);
- продемонстрировать передачу данных и обновление информации.

Для Linux/Python можно рассмотреть `multiprocessing` и `Pipe`. Реализация должна быть именно межпроцессной, а не просто отдельным окном/потоком внутри GUI.

### 3.2. Мониторинг процессов

Для последней цифры зачётной книжки **5** требуется отслеживать **все процессы ОС, кроме процессов, запущенных из разрабатываемого приложения**.

Минимум:
- список процессов;
- PID и имя процесса;
- время запуска;
- обновление списка;
- исключение собственных процессов приложения из мониторинга.

Дополнительно полезно показывать выбранный процесс: пользователя, статус, CPU, RAM и количество потоков — если эти данные доступны.

### 3.3. Встроенный терминал Linux

Для нечётного номера (5) требуется набор команд для:
- **управления процессами**;
- **работы с устройствами ввода/вывода**.

Требование методички: не менее **10 команд**, реализация команд — в виде системных вызовов/системных средств, предусмотрена справка.

Планируемый интерфейс терминала:
- консольный вид: поле вывода и строка ввода;
- запуск из главного окна;
- вывод stdout/stderr, кода завершения и ошибок;
- история введённых команд (желательно);
- встроенная справка по доступным командам.

Предварительный набор команд (точный список и реализацию согласовать с преподавателем):
1. `ps` — список процессов;
2. `top` или аналог — текущая активность процессов;
3. `kill` — завершение процесса по PID;
4. `pkill` — завершение процесса по имени (с ограничениями/подтверждением);
5. `nice` — запуск с заданным приоритетом;
6. `renice` — изменение приоритета процесса;
7. `pgrep` — поиск PID по имени;
8. `lsof` — открытые файлы/дескрипторы процесса;
9. `lsusb` — USB-устройства;
10. `lspci` — PCI-устройства;
11. `lsblk` — блочные устройства;
12. `udevadm` — сведения об устройствах (выбор безопасных подкоманд).

Команды, требующие повышенных прав, не должны автоматически запускаться через `sudo`. Перед потенциально опасными действиями нужно предупреждение/подтверждение. Уточнить у преподавателя, допустим ли запуск системных утилит через `subprocess`, поскольку в методичке указано, что реализация должна быть в виде системных вызовов.

### 3.4. Дополнительная функция (пункт 4 методички)

Преподаватель индивидуально назначает один или несколько пунктов из перечня функций (1–50).

**Если мой «вариант 5» означает функцию №5 в перечне, то это:**
- получение информации о звуковой карте/аудиоустройствах;
- отображение сведений в приложении;
- сохранение результата в лог-файл;
- обновление в реальном времени, если информация динамическая (для статических сведений достаточно обновления по запросу).

**Это предположение — подтвердить назначенный преподавателем пункт.**

## 4. Функциональные требования к файловому менеджеру

### 4.1. Рабочая директория приложения
- создать отдельную корневую папку приложения;
- в интерфейсе показывать содержимое этой корневой папки и её вложенных папок;
- создать папку `System` для файлов, необходимых приложению;
- `System` нельзя удалить, переименовать или переместить;
- создать `Корзина` (Trash);
- поддержать пользовательские папки.

### 4.2. Операции с файлами и каталогами
- открытие файла средствами ОС/приложением по умолчанию;
- создание каталога;
- копирование;
- перемещение;
- переименование;
- удаление в Корзину;
- безвозвратное удаление;
- восстановление из Корзины;
- обработка ошибок (нет доступа, файл занят, имя уже существует, путь отсутствует и т. п.).

### 4.3. Интерфейс
- главное меню;
- контекстное меню по правому клику;
- пункт «О программе» с названием дисциплины, языком, автором и группой;
- пункт «Справка» с горячими клавишами и описанием функций;
- Drag and Drop;
- минимум 5 горячих клавиш;
- поиск файлов и папок внутри вложенных каталогов;
- отображение съёмных носителей и переход к ним/работа с ними.

Пример горячих клавиш (можно изменить):
- `Ctrl+C` — копировать;
- `Ctrl+X` — вырезать;
- `Ctrl+V` — вставить;
- `F2` — переименовать;
- `Delete` — переместить в Корзину;
- `Shift+Delete` — удалить безвозвратно (с подтверждением);
- `Ctrl+F` — поиск;
- `Ctrl+N` — создать папку.

### 4.4. Системные утилиты
Из приложения должна быть возможность запускать системные утилиты Linux, например:
- терминал;
- монитор ресурсов;
- системные настройки/управление компьютером;
- утилиты для работы с дисками и устройствами (в зависимости от доступных программ).

## 5. Дополнительные окна и IPC

Сделать окно/окна, которые запускаются отдельными процессами и получают данные от основного приложения.

Предлагаемый сценарий:
1. Пользователь открывает дополнительное окно из меню.
2. Главное приложение собирает необходимые данные.
3. Данные передаются дочернему процессу через Pipe.
4. Дочернее окно отображает данные.
5. При обновлении данные повторно передаются по каналу.
6. При закрытии главного окна дочерние процессы корректно завершаются.

Важно: PyQt не рекомендуется бездумно создавать GUI в multiprocessing-процессах. Продумать запуск процесса, передачу данных, завершение и совместимость с Qt event loop.

---

## 6. Монитор процессов

Экран/вкладка мониторинга:
- таблица процессов;
- колонки: PID, имя, пользователь, время запуска, статус;
- сортировка и поиск/фильтр;
- обновление по таймеру;
- исключать процессы, запущенные самим приложением;
- выбор процесса и просмотр дополнительной информации;
- возможность сохранить отчёт о процессах, запущенных во время работы «Суперапп», как требует минимальный функционал методички (имя и время старта).

Для работы с процессами в Python можно изучить `psutil`, но сверить с преподавателем, подходит ли библиотека для требований работы.

---

## 7. Логи и сохранение данных

- дополнительная системная информация должна сохраняться в текстовый лог;
- предусмотреть выбор имени/пути файла пользователем;
- логировать основные действия файлового менеджера (по возможности): открытие, копирование, перемещение, удаление, создание папки, ошибки;
- отчёт о процессах, запущенных во время работы приложения, сохранять в текстовый файл (имя процесса и время старта);
- лог-файлы не должны сохраняться в защищённую от изменения папку `System`, если это не требуется архитектурой.

---

### Технологии/библиотеки для изучения
- `PyQt6` — GUI;
- `pathlib`, `shutil`, `os` — работа с файловой системой;
- `subprocess` — запуск внешних системных программ (с безопасной обработкой аргументов);
- `multiprocessing` / `Pipe` — IPC и отдельные процессы;
- `psutil` — сведения о процессах и ресурсах (если допустимо по требованиям);
- `QTimer` — периодическое обновление интерфейса;
- `QFileSystemModel` / `QTreeView` / `QTableView` — представление файлов и данных;
- `QSettings` — настройки приложения (опционально).
